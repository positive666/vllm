1 · Problem and contract

Retire original APC reservations after full-prefix retries

An APC hit may shrink after a tail lookup reserved host-cache readers. A full-prefix retry replaces active Session metadata. A later cleanup resolved from the replacement can miss the original tail or decrement another reader. A globally shared lock generation is not sufficient to identify the request's remaining shares.

Snapshot the old packed-token identity, hit bounds, attention windows, owners and generations together with only the unclaimed per-key read shares under the Session lock. Resolve original keys before claiming this snapshot once; worker-owned receipts settle independently. Retain one snapshot and decline further lookup admission until it is claimed. Follow upstream #6252: missing-registration RETRIEVE returns False without claiming or immediately releasing a share. Delete that helper and its unused Session epoch. Retain the required begin_lookup window argument, prefetch_group_windows and resolver window override specifically for original APC cleanup.

This is a correctness/lifetime fix. No model-quality, TTFT or throughput improvement is claimed. Fresh results and historical controls are distinguished below.

2 · Before / after

Before · failure schedule

  1. Tail lookup retains readers
  2. APC shrinks; full lookup replaces metadata
  3. Old FREE consults new boundaries or reader count
  4. Original tail leaks, or peer protection is consumed

After · ownership barrier

  1. #6063 fences old RPC acknowledgments
  2. Snapshot only original unclaimed shares
  3. Resolve old identity and window before claim
  4. Release once; worker receipts settle separately

3 · End-to-end responsibility flow

  1. vLLM connector / scheduler adapterAfter a final prefetch result, detect APC shrink and record the abandoned range. #6063 orders old LOOKUP/status/FREE acknowledgments before replacement submission. Failed prerequisites return a miss rather than pretending the old handler is gone.
  2. Session.begin_lookupUnder one lock, capture the original metadata and unclaimed L1ReadReservation entries, then reset current lookup state. Reject another lookup while a snapshot remains. Claims already handed to workers belong to their completion receipts.
  3. LookupModule.free_lookup_locksOrdinary FREE uses the current lookup ledger. Each abandoned extra range matches old packed identity and hit bounds, resolves keys from old windows, then claims the snapshot. Filter the old unclaimed receipts by these resolved keys.
  4. StorageManager / #6067 transfer completionfinish_read_reservations routes the exact original owner, generation and count. Worker completions independently release their immutable ownership. No original reader count is reconstructed; a peer's share must remain locked.

The numbered sequence explains the intended protocol order, not a promise of serial execution across hosts. Failure handling and boundaries are stated below.

7 · Alternatives, compatibility and rollout

Re-resolving with current Session metadata loses the original identity; remembering only token ranges loses windows/owners/generations; reconstructing num_kv_readers double-counts already-owned shares. A timeout cannot prove that an old RPC or transfer has completed. Keep an explicit bounded snapshot plus acknowledgments and per-request receipts. Broader wire attempt IDs are a separate protocol change.

Keep dependency order and test the deployed composition. Reverting a lifetime fix may reintroduce the original race; use a controlled rollback to a known whole configuration rather than mixing partial contracts. No live service rollout was performed in this review refresh.

1 · 问题与契约

全前缀重试后按原始所有权回收 APC 读预留

APC 命中可能在尾部查询预留主机缓存读份额后缩短。全前缀重试会替换 Session 当前元数据，随后若按新元数据清理，可能漏掉原尾部或误减其他读者。共享锁代次不足以标识请求剩余的读份额。

在 Session 锁内保存旧打包 token 身份、命中边界、注意力窗口、所有者、代次及仍未认领的逐 key 读份额。先解析原始 key，再一次性认领快照；worker 已持有的回执独立结算。最多保留一个快照，认领前拒绝后续查询。遵循上游 #6252：注册缺失的 RETRIEVE 直接返回 False，不认领或立即释放份额，删除相关 helper 和不再使用的 Session epoch。为原始 APC 清理保留 begin_lookup 必传窗口参数、prefetch_group_windows 及 resolver 窗口覆盖。

这是正确性与生命周期修复，不宣称模型质量、TTFT 或吞吐提升。下文区分本轮结果与历史阴性对照。

原行为 · 失败时序

  1. 尾部查询预留读份额
  2. APC 缩短；全查询替换元数据
  3. 旧 FREE 使用新边界或重建读计数
  4. 旧尾部泄漏，或同伴保护被消耗

  1. #6063 等待旧 RPC 确认
  2. 仅快照原始未认领份额
  3. 按旧身份与窗口解析，再认领
  4. 一次性释放；worker 回执独立结算

3 · 端到端责任流程

  1. vLLM connector / scheduler adapter在最终预取结果后发现 APC 缩短并记录废弃范围。#6063 保证旧 LOOKUP/status/FREE 确认先于替换查询；前置 RPC 失败时返回 miss，不假装旧处理器已经结束。
  2. Session.begin_lookup在同一把锁内保存原元数据和未认领的 L1ReadReservation，之后才重置当前查询。仍有快照时拒绝另一次查询。已交给 worker 的份额由其完成回执持有。
  3. LookupModule.free_lookup_locks普通 FREE 使用当前查询台账。废弃 extra range 匹配旧打包身份与命中边界，依据旧窗口解析 key，然后认领快照；按解析结果筛选旧的未认领回执。
  4. StorageManager / #6067 transfer completionfinish_read_reservations 使用原始所有者、代次和计数路由。worker 完成时独立释放不可变所有权。不重建原读者数量，同伴份额必须保持加锁。

编号描述协议要求的先后关系，不表示跨主机串行执行；失败处理与保证边界见下文。
