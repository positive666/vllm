1 · Problem and contract

Pin L2 STORE sources until terminal completion

An L2 adapter can keep reading an L1 object after its reservation's TTL expires. The old store controller held only that expiring read lock; normal deletion could therefore recycle the allocation under accepted I/O. Its stop path also released every in-flight read lock before the adapter finished. A logical timeout or shutdown request is not proof that source reads ended.

Reuse #6067's generation-aware read pins. Each StoreController is bound to one L1 manager; each adapter batch obtains its own unique transfer tag. Only successfully pinned objects are submitted. A terminal success or failure releases that tag once, preserving other replicas and newer readers. Shutdown stops new admission, drains accepted work and then closes notifiers. Bigtable's unsharded preparation path now joins every sibling executor read before publishing a preparation failure.

This is a correctness/lifetime fix. No model-quality, TTFT or throughput improvement is claimed. Fresh results and historical controls are distinguished below.

2 · Before / after

Before · failure schedule

  1. L1 write commits; StorePolicy selects one or more L2 replicas.
  2. STORE borrows a MemoryObj under an expiring read reservation.
  3. TTL expires, or stop() drops the in-flight locks.
  4. delete() can succeed while an admitted adapter still reads the source.

After · ownership barrier

  1. Capture the original read generation on this controller's L1 manager.
  2. Validate the generation and pin with a unique per-replica transfer tag.
  3. TTL expiry cannot reclaim the pinned source; stop() waits for terminal results.
  4. Release only that task's pin after all its source reads end.

3 · End-to-end responsibility flow

  1. StorageManager / L1 ownerStorageManager constructs one StoreController for each L1 manager, with adapters selected by L1 affinity. The controller already knows its owner; this PR does not add cross-L1 routing.
  2. StoreListener → StorePolicyCommitted L1 writes enqueue keys. The loop asks the policy for replica targets, deduplicates keys per target and stops admitting new keys after shutdown starts.
  3. reserve_read → pin_read_buffersReserve the current generation, then atomically validate and pin it under l2-store-N. Failed pin claims release only their original generations. Successful pins supply the actual source objects for submission.
  4. L2AdapterInterfaceThe adapter returns a task ID once admitted. If submit_store_task raises, it must leave no source access outstanding. After admission, both success and failure results must be terminal buffer-access fences.
  5. Bigtable preparationFor unsharded writes, gather all executor preparation outcomes with return_exceptions=True, then re-raise a failure. A failed sibling cannot authorize completion while another thread still reads the source.
  6. Terminal result → finish_read_transferCompletion releases that task's tagged pins/reservations, updates policy/accounting and removes the tracked task. The same source can remain pinned by another replica.
  7. stop → drain → adapter.close → L1.closeStop closes key and runtime-adapter admission, applies previously accepted operations and polls in-flight stores to terminal results. StorageManager's existing close order keeps adapters and L1 alive during the drain; an adapter close failure leaves L1 open upstream.

The numbered sequence explains the intended protocol order, not a promise of serial execution across hosts. Failure handling and boundaries are stated below.

test_stop_drains_store_and_ignores_later_l1_writes

Both terminal outcomes must hold stop() pending and keep the source pinned while I/O is gated. Later keys are not stored; callbacks after close remain safe and runtime adapter add/remove are rejected after stop.

test_each_adapter_retains_its_own_store_pintest_rejected_replica_does_not_release_admitted_store

test_expired_pin_claim_preserves_newer_reader

Expire the reservation between reserve and pin, install a newer reader, and require rejected old-claim cleanup to preserve the new generation. This guards the pre-submission error boundary.

test_stop_finishes_adapter_operations_accepted_before_shutdown

Gate an add operation, accept a remove, then start shutdown. The accepted remove must complete instead of being left behind the loop's last drain.

test_failed_preparation_waits_for_other_source_readers

Using the existing fake Bigtable service and real executor threads, block one source read and fail its sibling. Require no completion notification/result until the blocked reader finishes, then require terminal failure. This validates local preparation ownership, not a real Google Cloud request.

test_submit_failure_releases_l1_read_locktest_read_lock_released_after_storetest_read_lock_released_after_all_adapters_complete

7 · Alternatives, compatibility and rollout

Increasing read TTL only moves the failure boundary; a per-task ownership pin represents actual access lifetime. Copying every STORE source would add memory and bandwidth cost without fixing terminal-result contracts. Unpinning on a controller timeout is unsafe. A worker process fence is separate work and is not enabled here.

Keep dependency order and test the deployed composition. Reverting a lifetime fix may reintroduce the original race; use a controlled rollback to a known whole configuration rather than mixing partial contracts. No live service rollout was performed in this review refresh.

1 · 问题与契约

固定 L2 STORE 源缓冲直至终态完成

L2 适配器可能在预约 TTL 到期后继续读取 L1 对象。旧 StoreController 仅持有可过期的读锁，普通删除可能在已接纳 I/O 仍读取时回收分配；停机路径也会在适配器完成前释放全部在途读锁。逻辑超时或停机请求不能证明源读取已经结束。

复用 #6067 的代际感知读 pin。每个 StoreController 绑定一个 L1 管理器；每个适配器批次使用独立 transfer tag，仅提交成功固定的对象。成功或失败终态只释放本 tag，保留其他副本与后来的读者。停机先停止接纳新工作，排空已接纳工作，再关闭通知器。Bigtable 非分片准备路径会等待所有同批 executor 读取结束，再发布准备失败。

这是正确性与生命周期修复，不宣称模型质量、TTFT 或吞吐提升。下文区分本轮结果与历史阴性对照。

2 · 前后行为对照

原行为 · 失败时序

  1. L1 写入提交；StorePolicy 选择一个或多个 L2 副本。
  2. STORE 在可过期的读预约下借用 MemoryObj。
  3. TTL 到期，或 stop() 释放在途读锁。
  4. 已接纳的适配器仍读取源缓冲时，delete() 已可能成功。

新行为 · 所有权屏障

  1. 在本控制器持有的 L1 管理器上记录原始读代际。
  2. 校验代际，并用每副本独立的 transfer tag 固定缓冲。
  3. TTL 到期不能回收已固定源缓冲；stop() 等待终态结果。
  4. 本任务全部源读取结束后，仅释放本任务的 pin。

3 · 端到端责任流程

  1. StorageManager / L1 ownerStorageManager 为每个 L1 管理器建立一个 StoreController，并按 L1 affinity 选择适配器。控制器已经持有自己的所有者；本 PR 不新增跨 L1 路由。
  2. StoreListener → StorePolicy已提交的 L1 写入把 key 加入队列。循环向策略查询副本目标，对各目标的 key 去重，并在开始停机后停止接纳新 key。
  3. reserve_read → pin_read_buffers先预约当前代际，再以 l2-store-N 原子校验并固定它。pin 认领失败时仅释放原代际；成功 pin 返回的对象才作为提交源。
  4. L2AdapterInterface工作被接纳后适配器返回任务 ID。submit_store_task 若抛异常，必须保证没有遗留源访问。接纳后的成功或失败结果都必须表示源访问已终止。
  5. Bigtable preparation非分片写入用 return_exceptions=True 收集全部 executor 准备结果，然后再抛出失败。一个同批任务失败不能在另一线程仍读源时授权完成。
  6. Terminal result → finish_read_transfer终态回执释放该任务带 tag 的 pin/预约，更新策略与计数并移除任务；同一源仍可被其他副本固定。
  7. stop → drain → adapter.close → L1.closestop 关闭 key 与动态适配器操作的接纳，处理此前已接纳的操作，并轮询在途 STORE 直至终态。StorageManager 既有关闭顺序在排空期间保持适配器和 L1 存活；上游在适配器关闭失败时保留 L1。

编号描述协议要求的先后关系，不表示跨主机串行执行；失败处理与保证边界见下文。
