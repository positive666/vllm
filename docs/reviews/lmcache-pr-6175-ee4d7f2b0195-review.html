本 Draft 集成可选的本地 Mooncake SDK 子进程隔离。上一次 CI 发现两个测试缺陷。本次提交修改三个测试文件，定位测试所选的安装包，核对子进程实际导入的路径，并校验预留张量存在。

原问题与修复

测试边界原行为修复后
父子进程导入根据测试源码目录推导产品路径，并改写 sys.path。父进程使用上游 lmcache_path 选定安装包，独立测试子进程从其实际导入的 lmcache 包定位组件。沿用私有 FD 调用方式，验证从源码目录外启动及移除原有 PYTHONPATH 的场景。
L1 缓冲区写入直接使用可能为空的张量。写入 3.5 前断言张量存在，继续执行淘汰、重载和数据值断言。

既有测试覆盖的运行链路

  1. 工厂通过私有 FD 和命名共享内存启动 worker。
  2. 测试使用该共享内存提交任务，模拟 SDK 可控地返回成功、失败或停滞。
  3. 释放失败传输前需要确认本地子进程退出或收到终态回执。远端网络与 DMA 的保证需要单独验证。

建议的源码审阅顺序

  1. 测试如何选择实际的进程客户端
  2. 检查子进程实际使用的安装包
  3. 恢复测试如何定位产品组件
  4. L1 分配和数据值校验
