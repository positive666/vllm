LMCache #6063 · Order replacement lookups and session end after acknowledgements

77e927223dd2c1402777ca3f995822764391ab1a · dev b1f50a83f2df · Full diff

What changed

Previous behavior

Finishing a scheduler lookup used to discard the futures for work already sent to a server. A replacement lookup or END_SESSION could reach that server while earlier work was still outstanding.

With the change

The lookup hands its outstanding RPC futures back during cleanup. Each server orders its own END after successful replies. An already acknowledged operation takes the immediate path.

Runtime sequence

  1. Submit LOOKUP and QUERY per server
  2. Retain already admitted RPCs at cleanup
  3. Wait for that destination's acknowledgements
  4. Start the replacement or send END

Connector configuration

The scheduler and worker use the official outbound-key resolver. Providing a key file selects its value. An absent setting passes the default through to the client factory. Configuration errors retain the upstream behavior. _connector_request_api_key · #6774

Review order

  1. Start with the handoff of pending RPC futures. close_and_take_pending_rpcs
  2. Follow the per-server callbacks and failed-predecessor handling. _OrderedSessionEnd
  3. Trace an unequal-hit replacement and its tail release. test_replacement_waits_for_the_old_unequal_hit_tail_ack

LMCache #6063 · 等已接纳的 RPC 确认后再重查和结束会话

77e927223dd2c1402777ca3f995822764391ab1a · dev b1f50a83f2df · 完整差异

行为变化

原来行为

调度器结束查找时，曾经会丢失已发给服务端的任务凭据。之前的任务尚未确认时，替换查找或 END_SESSION 就可能到达同一服务端。

修订后

清理查找时交接尚待确认的 RPC。每个服务端在自己的前序操作成功回复后收到 END。前序操作已确认时可以立即继续。

运行时顺序

  1. 向各服务端提交 LOOKUP、QUERY
  2. 清理时保留已接纳 RPC 的确认责任
  3. 等待对应服务端确认
  4. 发起重查或发送 END

连接器配置

调度器和 worker 均使用上游的出站凭证读取函数。配置文件路径时使用其内容，未配置时沿用客户端工厂的默认行为。错误配置沿用上游的报错方式。 _connector_request_api_key · #6774

建议审阅顺序

  1. 先看查找如何交接仍在途的 RPC。 close_and_take_pending_rpcs
  2. 沿着逐服务端回调核对前序操作失败时的行为。 _OrderedSessionEnd
  3. 查看各服务端命中长度不同时，重查如何等待尾部释放。 test_replacement_waits_for_the_old_unequal_hit_tail_ack

回归证据

Python 3.12，NVIDIA H20。319 项通过，0 项跳过，零失败、零错误。总数已包含上游 9 项出站凭证测试。

查找状态和调度适配器用例覆盖确认先后和每个服务端独立结束。凭证文件用例覆盖默认配置、无效文件，以及发往调度器和 worker 客户端的凭证。 上游适配器测试
