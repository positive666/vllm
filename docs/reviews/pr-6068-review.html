[Bugfix][MP] Retire original APC reservations after full-prefix retries

An APC shrink changes the active lookup, not the ownership of its abandoned locks. Capture one original reservation and retire only its remaining shares.

1 · Problem, behavior and boundaries

Previous behavior

A partial lookup skips vLLM’s APC prefix. If APC shrinks, the connector retries from token zero. Resolving an old FREE with replacement windows, registration or tail metadata can leak the abandoned reservation or decrement another request’s shared read count.

Behavior at this head

Session snapshots original identity, windows, owner routing, generations, unclaimed read receipts and unfull-tail keys under one lock before replacement. Cleanup resolves those original keys and atomically claims the snapshot once. The current bounded-replay tail has its own ordinary FREE range.

Stacked on #5478, #6063 and #6067. #5383 introduced APC retries and #5976 addressed alignment; this increment preserves original reservation authority. #6070 is not included.

2 · End-to-end implementation walkthrough

  1. The connector freezes a chunk-aligned APC boundary. A later shrink sets sticky need_full_lookup and records the abandoned interval in pending_free_ranges; the replacement asks LMCache for the full prefix instead of handing the gap back for recomputation.
  2. The #6063 acknowledgement fence must finish earlier LOOKUP/status/FREE handlers before the replacement reuses the ID. This snapshot does not infer an attempt from an identical wire key.
  3. Session.begin_lookup captures AbandonedPrefetch together with the original packed tokens, group windows, owners, generations and only the remaining unclaimed shares. A worker receipt already handed out remains independent of replacement.
  4. Only one abandoned reservation is retained. A further lookup is declined as a miss until it is claimed. Ordinary lookup and CacheBlend’s prefix leg both honor this admission result instead of reporting stale hits.
  5. FREE extra_ranges resolve keys against the old snapshot. Resolution failure leaves it retryable. claim_abandoned_prefetch then consumes authority once; a later partial release failure cannot authorize a second decrement of a peer’s shares.
  6. The old unfull-tail boundary and exact ObjectKeys are captured rather than reconstructed from replacement registration. A repeated FREE has no old authority left and cannot consume replacement shares.
  7. pending_replay_tail represents the current lookup’s bounded-replay tail, while pending_free_ranges identifies an abandoned APC attempt. Equal numeric intervals do not make the reservations interchangeable; the replay tail uses the ordinary FREE key.
  8. The unit of authority is an original read share, not an object key alone. Prefetch records the actual read count and generation for every retained ObjectKey. Counts can differ across KV groups and replicated MLA workers.
  9. Session.claim_worker_read atomically transfers one available share per key to a registered worker incarnation. Session.claim_free_reads takes only unclaimed shares. Disjoint ranges remain valid; the same instance cannot claim overlapping keys twice.

5 · Risks and focused review questions

1 · 问题、行为与边界

原有行为

部分 lookup 跳过 vLLM 的 APC 前缀。APC 缩减后，连接器从 token 0 重试。若用替换后的窗口、注册或尾块元数据解析旧 FREE，可能泄漏废弃预留，也可能扣减其他请求的共享读取计数。

此 head 的行为

Session 在替换前用同一把锁捕获原身份、窗口、所有者路由、代次、未领取读取凭据与未满尾块键。清理先解析原始键，再原子地领取一次快照。当前 bounded-replay 尾部通过独立的普通 FREE 范围释放。

基于 #5478、#6063 与 #6067。#5383 引入 APC 重试，#5976 处理对齐；本增量保留原始预留权限。不包含 #6070。

2 · 端到端实现讲解

  1. 连接器冻结块对齐的 APC 边界。之后缩减时设置粘性的 need_full_lookup，并把废弃区间记入 pending_free_ranges；替换 lookup 请求 LMCache 提供全前缀，不把缺口交回重算。
  2. #6063 确认屏障必须先完成此前 LOOKUP/状态/FREE 处理器，替换 lookup 才能复用 ID。本快照不能从相同线协议键推断尝试身份。
  3. Session.begin_lookup 捕获 AbandonedPrefetch，其中包含原始打包 token、组窗口、所有者、代次与仍未领取的份额。已经交给 worker 的凭据独立于替换而存在。
  4. 只保留一个废弃预留。在它被领取前，再次 lookup 按 miss 拒绝。普通 lookup 与 CacheBlend 前缀路径都遵守此准入结果，不报告旧命中。
  5. FREE 的 extra_ranges 使用旧快照解析键。解析失败时仍可重试；claim_abandoned_prefetch 随后一次性消耗释放权限。之后即使发生部分释放失败，也不能再次扣减其他读者份额。
  6. 旧未满尾块的边界与精确 ObjectKey 被捕获，而不使用替换后的注册重建。重复 FREE 已无旧释放权限，不能消耗替换 lookup 的份额。
  7. pending_replay_tail 表示当前 lookup 的 bounded-replay 尾部，pending_free_ranges 标识废弃 APC 尝试。数值相同的区间仍是不同预留；replay 尾部通过普通 FREE 键释放。
  8. 释放权限以原始读取份额为单位，不能只依赖对象键。预取为每个保留的 ObjectKey 记录实际读取计数与代次；不同 KV 组和 MLA 副本的计数可能不同。
  9. Session.claim_worker_read 原子地把每个键的一个可用份额交给已注册的 worker 实例。Session.claim_free_reads 只能取走尚未交给 worker 的份额。互不重叠的范围可以分别领取，同一实例不能重复领取重叠键。
