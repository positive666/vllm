[Bugfix][MP] Retire successful eager sessions after final store reports

PR #6020 · bc60e59b77af351679b90112271ae54db606f0eb

dev 427b6fa8769922b03f9b6bd3c1ea2928b0ce0d54

Problem and result

Before

A successful eager request can finish before its final STORE reaches the MP server. An immediate END_SESSION lets that late handler create a new orphan session.

After

Keep successful eager sessions pending until aggregated finished_sending reports complete. An older completed chunk cannot authorize a newer pending STORE. Completed False results also count as terminal reports.

This refresh preserves runtime behavior from the existing PR and adapts renamed token/future imports. Retirement tests use independent copies of the current vLLM empty output instead of its removed constructor field.

Lifecycle and ownership

1. Request finishes
2. Record pending session
3. Collect all worker reports
4. END_SESSION and retire lookup

A missing rank keeps retirement pending. Worker-loss recovery, unknown DMA completion and RPC exceptions remain outside this change. Aborted requests are covered by dependent #6070.

问题与结果

修复前

正常结束的 eager 请求可能早于最终 STORE 到达服务端。此时立即 END_SESSION 会使迟到的 STORE 重建孤立会话。

修复后

成功结束的 eager 会话等待聚合的 finished_sending 回执。旧 chunk 的完成不能放行新的在途 STORE。结果为 False 的已完成任务也计为终态。

此次同步保留已有 PR 的运行行为，并适配迁移后的 token/future 导入。退休测试通过复制当前 vLLM 空输出构造独立对象，以兼容已移除的构造字段。

生命周期与所有权

1. 请求结束
2. 登记待退休会话
3. 收齐全部 worker 回执
4. END_SESSION 并清理查询

缺少某个 rank 回执时继续等待。本修复不处理 worker 丢失恢复、未知 DMA 完成状态和 RPC 异常。中断请求由依赖本修复的 #6070 处理。
