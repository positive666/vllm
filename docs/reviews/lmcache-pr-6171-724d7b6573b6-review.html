dev 243f95a64c1b · 724d7b6573b6408de86c4aee1eacc80d0ac3aa9d · Full difference and commit history

Before

An L2 writer can still read L1 bytes after the ordinary read TTL expires. A source eligible for deletion at that point may be recycled before the adapter replies.

After

Pin admitted STORE sources using a task-bound transfer identity. Release only the relevant pins after each terminal outcome. Close admission before draining pending stores. Apply upstream’s current store policy and manager selection.

Keep upstream #5863's admission watermark and unlocked waiting queue. Charge a submitted object's physical L1 bytes once across adapters and until the last relevant terminal completion. Shutdown discards queued entries and drains accepted stores before adapters close.

Sequence

  1. Write admitted
  2. source pinned
  3. adapter finishes or fails
  4. controller releases its pin

LMCache #6171 · [Bugfix][MP] Pin L2 STORE sources until terminal completion

dev 243f95a64c1b · 724d7b6573b6408de86c4aee1eacc80d0ac3aa9d · 完整差异和提交历史

原行为

普通读锁到期后，L2 写入仍可能读取 L1 字节。若此时允许删除，适配器返回前源内存就可能被复用。

修复行为

给已接纳的 STORE 增加按任务区分的源引用。收到对应终态才释放，关闭时先停止接纳再排空待完成写入。沿用上游的存储策略和 L1 选择方式。

保留上游 #5863 的接纳水位和无锁等待队列。已提交对象的物理 L1 字节在多适配器间只计一次，直到最后一个相关写入出现终态。停机丢弃排队项，排空已接纳的写入后再关闭适配器。

生命周期

  1. 接纳写入
  2. 固定源块
  3. 适配器成功或失败
  4. 控制器释放该次引用

建议审阅顺序

  1. _drain_l2_store_completions
  2. pin_read_buffers
  3. stop
