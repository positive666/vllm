LMCache #6020 · [Bugfix][MP] Retire successful eager sessions after final store reports

46e2a10775051bc6752a4c31cf09555a8d1a00c1

A successful eager request can finish before its last STORE runs. END_SESSION removes the session, then a late STORE handler recreates it.

The four-file change covers the eager scheduler, the worker adapter, role tests, and retained-boundary tests. The abort extension is tracked by #6070.

What changes at request completion

SituationPrevious behaviorWith this change
normal stop or length capAn outstanding STORE can outlive END_SESSION.Defer session retirement while a final report is due.
Earlier chunk complete, later STORE still pendingThe original worker could report too early.Exclude request IDs that still have STORE futures.
No STORE or retained boundaryImmediate cleanup on eager path.Immediate cleanup.

Scheduler and worker sequence

  1. Scheduler sees the final request status. Scheduled STORE work or retained boundary blocks already require delayed release.
  2. Worker waits for the last outstanding STORE future and reports finished_sending. A STORE result of False is terminal too.
  3. vLLM aggregates worker reports. One missing rank leaves the request pending.
  4. The scheduler receives the aggregate, calls end_session and cleanup_lookup_result, then removes the pending entry.

请求结束时行为如何变化

触发条件原行为修复后
正常停止或达到长度上限STORE 可能在 END_SESSION 之后才执行。需要最终报告时，推迟会话收尾。
早期块已完成，较新的 STORE 仍在执行原 worker 可能提前报告。过滤仍有 STORE future 的请求 ID。
没有 STORE 或保留的边界块eager 路径直接收尾。直接收尾。

调度端和 worker 的执行顺序

  1. 调度端得到请求终态。已调度的 STORE 或保留的边界块需要延迟释放。
  2. worker 等待最后的 STORE future 结束并报告 finished_sending。STORE 返回 False 也属于终态。
  3. vLLM 汇总各 rank 的报告。缺少任一 rank，仍保留待办状态。
  4. 调度端收到聚合结果，依次执行 end_session、cleanup_lookup_result，随后移除待办记录。
