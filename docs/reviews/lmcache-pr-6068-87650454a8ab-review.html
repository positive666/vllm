LMCache #6068 · Retire the original APC reservations after a full-prefix retry

87650454a8ab3216c81677fcffbe52f5db766fef · dev b1f50a83f2df · Full diff

What changed

Previous behavior

A retry can replace the first automatic prefix caching (APC) lookup with a different token range. A late cleanup can then refer to the new range or a different reader's share.

With the change

Snapshot the earlier keys, owners, generations, lookup geometry and unclaimed shares. Resolve original keys before claiming one release attempt. A partially completed release leaves any remainder to lease expiry.

Runtime sequence

  1. Record the partial lookup
  2. Preserve the original read reservations
  3. Retry with the full prefix
  4. Resolve the old keys and claim one release

Connector configuration

The scheduler and worker use the official outbound-key resolver. Providing a key file selects its value. An absent setting passes the default through to the client factory. Configuration errors retain the upstream behavior. _connector_request_api_key · #6774

Review order

  1. Check when a pending reservation is captured and which worker shares have already been claimed. begin_lookup
  2. Follow the original tokens, group geometry and object identity through FREE. free_lookup_locks
  3. Check the single release authorization after resolution. claim_abandoned_prefetch
  4. Inspect the peer-reader assertion and the adjacent partial-release tests. test_repeated_apc_cleanup_cannot_release_peer

Engineering limits

After a partial release, replay could consume a peer reader. Unreleased shares can remain until lease expiry. Long-running multi-host serving and throughput are outside this validation.

LMCache #6068 · 全前缀重查后按原始预留清理 APC 读份额

87650454a8ab3216c81677fcffbe52f5db766fef · dev b1f50a83f2df · 完整差异

行为变化

原来行为

自动前缀缓存（APC）重查时可能替换原始 token 范围。迟到的清理可能引用新范围，或误用其他读者的份额。

修订后

重查时保存原键、所有者、代际、查找几何和未领取份额。先解析原键，再领取一次释放机会。释放部分完成时，剩余份额依靠租约到期回收。

运行时顺序

  1. 记录部分查找
  2. 保存原始读预留
  3. 按完整前缀重查
  4. 解析原键并领取一次释放机会

连接器配置

调度器和 worker 均使用上游的出站凭证读取函数。配置文件路径时使用其内容，未配置时沿用客户端工厂的默认行为。错误配置沿用上游的报错方式。 _connector_request_api_key · #6774

建议审阅顺序

  1. 先看何时保存原预留，哪些 worker 份额已被领取。 begin_lookup
  2. 沿 FREE 核对原 token、分组几何和对象标识。 free_lookup_locks
  3. 核对完成解析后仅发放一次的释放权限。 claim_abandoned_prefetch
  4. 查看其他读者的份额断言和相邻的部分释放测试。 test_repeated_apc_cleanup_cannot_release_peer

回归证据

Python 3.12，NVIDIA H20。596 项通过，0 项跳过，零失败、零错误。总数已包含上游 9 项出站凭证测试。
