Scheduler and worker sequence

  1. Scheduler sees the final request status. Scheduled STORE work or retained boundary blocks already require delayed release.
  2. Worker waits for the last outstanding STORE future and reports finished_sending. A STORE result of False is terminal too.
  3. vLLM aggregates worker reports. One missing rank leaves the request pending.
  4. The scheduler receives the aggregate, calls end_session and cleanup_lookup_result, then removes the pending entry.

调度端和 worker 的执行顺序

  1. 调度端得到请求终态。已调度的 STORE 或保留的边界块需要延迟释放。
  2. worker 等待最后的 STORE future 结束并报告 finished_sending。STORE 返回 False 也属于终态。
  3. vLLM 汇总各 rank 的报告。缺少任一 rank，仍保留待办状态。
  4. 调度端收到聚合结果，依次执行 end_session、cleanup_lookup_result，随后移除待办记录。
