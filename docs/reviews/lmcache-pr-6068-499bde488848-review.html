Before

When an APC range shrinks and a full-prefix lookup replaces it, delayed or repeated cleanup may act on the replacement range or remove a peer’s share.

After

Snapshot the original keys, owners, generations, windows and still-unclaimed shares at replacement. Retire that snapshot once, including unfull tail chunks. Preserve the official session, lookup and RPC ordering interfaces.

Superseded APC reads resolve against the original session token hasher, original windows and original object identities. Primary requests still use upstream's registered geometry. A third overlapping attempt cannot overwrite a pending reservation.

Sequence

  1. Partial lookup
  2. snapshot original
  3. full lookup
  4. late/duplicate FREE resolves original only

Suggested review order

  2. claim_abandoned_prefetch
  3. free_lookup_locks

原行为

APC 范围缩小并改成全前缀重查后，延迟或重复清理可能误用新范围，或释放另一个请求的份额。

修复行为

替换时保存原来的键、所有者、代际、窗口和未领取份额。按快照只清理一次并包含尾块。兼容上游的 session、lookup 及 RPC 顺序。

被替换的 APC 查找沿用原会话的哈希器、窗口和对象标识。当前查找使用上游注册的分块参数。仍有待清理预留时，第三次重查不能覆盖快照。

生命周期

  1. 部分查找
  2. 保存原预留
  3. 全量重查
  4. 迟到或重复 FREE 仅处理原预留

建议审阅顺序

  1. get_abandoned_prefetch
  2. claim_abandoned_prefetch
  3. free_lookup_locks
