[Bugfix][MP] Keep RETRIEVE source ownership through device completion

Separate cancellable lookup reservations from sources already owned by device I/O. A read TTL bounds a lease; only device completion ends an admitted transfer.

1 · Problem, behavior and boundaries

Previous behavior

FREE and a delayed RETRIEVE completion could both decrement the same anonymous reader share. Expiry could also make a source evictable while asynchronous H2D still read its bytes; a key-only late completion could affect a later reader.

Behavior at this head

Prefetch propagates original generations and actual reader counts into Session. FREE and workers claim disjoint shares, and RETRIEVE copies only from generation-validated pinned objects. A detached completion receipt holds each source until the stream finishes.

Includes the unmerged generation-aware cleanup prerequisite #5478 with retained authorship. #5673 protects LOAD destinations; #6171 extends these source pins to L2 STORE; #6068 owns abandoned APC snapshots.

2 · End-to-end implementation walkthrough

  1. The unit of authority is an original read share, not an object key alone. Prefetch records the actual read count and generation for every retained ObjectKey. Counts can differ across KV groups and replicated MLA workers.
  2. Session.claim_worker_read atomically transfers one available share per key to a registered worker incarnation. Session.claim_free_reads takes only unclaimed shares. Disjoint ranges remain valid; the same instance cannot claim overlapping keys twice.
  3. pin_read_buffers validates the original generation while holding the L1 manager mutex. A unique transfer tag prevents ordinary deletion, eviction, clear and temporary-object cleanup from reclaiming the source until finish_read_transfer.
  4. The completion receipt captures the original owner, key, generation and tag. It survives Session removal or replacement. Finishing an expired generation removes its pin without decrementing a later reader; repeated completion has no second effect.
  5. Shadow L1 implements the same interface over a borrowed view. Pins defer returning that local view, but never extend the peer owner’s lease. An ended peer lease rejects a new pin; a local TTL sweep retains a still-pinned view.
  6. Full chunks and unfull tails use one ownership ledger. The tail copy helper receives the already pinned MemoryObj rather than looking up a mutable key again. A tail-only RETRIEVE cannot bypass source ownership.
  7. If completion recording or callback publication fails, the handler synchronizes the stream before releasing the tag. A failed synchronization leaves pins in place. Ordinary documented pin errors settle their original claimed shares without touching a newer generation.

3 · Alternatives and responsibility boundaries

5 · Risks and focused review questions

  • The wire key has no lookup-attempt ID and an instance ID does not prove stable physical-rank identity across reconnects. Arbitrary delayed replays or request-ID reuse remain unsupported.
  • Unexpected exceptions after partial pin admission can leave unvisited shares until TTL. Explicit force deletion remains unsafe during active I/O. Sparse CacheBlend ownership and APC abandoned-snapshot retirement are separate scope.
  • Shadow pins do not fence peer-side recycling after the owner’s lease ends. No full-model serving, Mooncake/RDMA teardown, production soak or performance/accuracy result is established by focused contract checks.

Suggested review order

  1. Read asynchronous resident-read contracts, then review L1 generation and pin state transitions.
  2. Trace actual prefetch reader counts through Session claims and original-owner completion grouping.
  3. Follow full/tail RETRIEVE and failure completion paths; then inspect lease-expiry, peer-reader and Shadow regressions.

让 RETRIEVE 源所有权保持到设备复制完成

1 · 问题、行为与边界

原有行为

FREE 和延迟的 RETRIEVE 完成可能重复扣减同一匿名读取份额。租约到期还可能在异步 H2D 读取期间使源缓冲区可驱逐；只按键处理的迟到完成可能影响新读者。

此 head 的行为

预取把原始代次和实际读取计数传入 Session。FREE 与 worker 领取互斥的份额；RETRIEVE 只从通过代次校验且已 pin 的对象复制。独立完成凭据将每个源保留到流执行结束。

包含尚未合并的代次清理前置项 #5478，并保留作者署名。#5673 保护 LOAD 目标；#6171 将源 pin 扩展到 L2 STORE；#6068 处理废弃 APC 快照。

2 · 端到端实现讲解

  1. 释放权限以原始读取份额为单位，不能只依赖对象键。预取为每个保留的 ObjectKey 记录实际读取计数与代次；不同 KV 组和 MLA 副本的计数可能不同。
  2. Session.claim_worker_read 原子地把每个键的一个可用份额交给已注册的 worker 实例。Session.claim_free_reads 只能取走尚未交给 worker 的份额。互不重叠的范围可以分别领取，同一实例不能重复领取重叠键。
  3. pin_read_buffers 在 L1 管理器互斥锁内校验原始代次。唯一传输标签阻止普通删除、驱逐、清空和临时对象回收；finish_read_transfer 才解除对源缓冲区的保护。
  4. 完成凭据捕获原始所有者、键、代次和标签，Session 删除或替换后仍有效。旧代次完成时解除自己的 pin，但不会扣减新读者的计数；重复完成不会再次生效。
  5. Shadow L1 在借用视图上实现同一接口。pin 延迟归还本地视图，但不会延长远端所有者的租约。远端租约已结束时拒绝新 pin，本地 TTL 扫描保留仍被 pin 的视图。
  6. 完整块与未满尾块共用一个所有权账本。尾块复制辅助函数接收已 pin 的 MemoryObj，不再重新查询可能变化的键。只含尾块的 RETRIEVE 也不能绕过源所有权。
  7. 若记录完成事件或发布回调失败，处理器先同步流再释放标签；同步失败则保留 pin。文档规定的 pin 错误只结算原始已领取份额，不影响新代次。

5 · 风险与聚焦审阅问题

  • 线协议键没有 lookup 尝试 ID，实例 ID 也不能证明重连前后物理 rank 的稳定身份。不支持任意迟到重放或请求 ID 复用。
  • 部分 pin 已接纳后发生意外异常，未访问的份额可能保留到 TTL。活动 I/O 期间强制删除仍不安全。稀疏 CacheBlend 所有权与 APC 废弃快照退休属于独立范围。
  • Shadow pin 不能阻止远端租约结束后的远端回收。聚焦契约检查不能证明完整模型服务、Mooncake/RDMA 关闭语义、生产长稳或性能/准确率结果。

建议审阅顺序

  1. 先读异步 resident-read 契约，再检查 L1 代次与 pin 状态转换。
  2. 跟踪实际预取计数如何进入 Session 领取与原所有者完成分组。
  3. 跟踪完整块/尾块 RETRIEVE 与失败完成路径，再检查租约到期、并发读者和 Shadow 回归。
